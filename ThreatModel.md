# Threat model

The worker protects lease ownership and limits the damage one serving instance can do to the host or its peers. A deployment also needs to protect the correspondence between each interface, its configuration, and its private lease state. The intended environment is an isolated lab link whose administrator controls which systems may offer DHCP service.

## Trust boundaries

Treat all incoming packet fields as untrusted, including MAC addresses, client identifiers, requested addresses, and conflict reports. The kernel and systemd supply the interface identity, ingress metadata, dynamic user, socket, and filesystem view. The host administrator controls those inputs, the lab topology, the installed units and binary, and the YAML. A configuration error can affect every client on the link, including its routes, resolvers and boot settings.

Each worker is trusted to follow its configured pool and the protocol decisions in the [technical specification](TechnicalSpecification.md). Assume a compromised worker can use its existing descriptors and modify its own writable state. Host root, the kernel, and the software release authorities are shared trust dependencies. The daemon exposes no administrative login, network management API, or updater. Installation, authentication of administrators and release verification happen outside it.

## Threats and limits

| Threat | What constrains it | What remains exposed |
| --- | --- | --- |
| Forged client identity, RELEASE or DECLINE | Ownership checks require the matching client claim, address and binding state. A decline can quarantine only a matching offer or lease. | Claims are observable and replayable on the link. A matching forgery can affect its victim. Restrict client admission and use trusted DHCP server ports or switch snooping where available. A rogue server can configure clients independently of this worker. |
| Wrong-link or malformed requests | A device-bound socket, kernel ingress metadata, original link identity, and bounded option parsing constrain the packet handler. Relay fields and inconsistent request forms are rejected. | A packet arriving on the expected device proves ingress there. Its original sender may be elsewhere if the network forwards traffic. Administrators own VLAN isolation and forwarding policy. A final send can race a host link change. |
| Resource or pool exhaustion | Per-worker admission limits, a separate allowance for known renewals, capped offers, bounded packet logs, and unit CPU, memory and task limits contain some load. | Traffic can consume host receive capacity before admission. Valid-looking clients can occupy the pool, and slow durable storage can delay renewals. Monitor pool pressure and renewal availability. There is no guaranteed throughput under hostile load. |
| Configuration substitution or stale state | Trusted YAML paths, a private per-instance state directory, stable exclusive lock, commit-before-ACK, and conservative restart deadlines protect normal operation. Invalid or incompatible state stops startup. | An authorized writer can remove or roll back a snapshot. A missing file is indistinguishable from first use. Fence competing allocators and follow the recovery procedure before reusing a pool. An armed socket can still receive traffic after a worker fails. |
| Code execution in a worker | The service runs under its own dynamic identity with empty capability sets, no-new-privileges, syscall and filesystem restrictions, and new sockets limited to netlink and UNIX. Strict Landlock applies to all threads before serving. | Workers share the host network namespace. The inherited UDP socket remains usable and packet-handler destination checks run in the compromised process. The sandbox cannot guarantee confinement of arbitrary UDP content or destinations. The worker can also corrupt its own leases. |
| Loss or disclosure of operational data | Snapshots are private. Worker events use fixed reason codes, omit raw packets and client identifiers, and bound log volume. | DHCP traffic is visible on-link. Snapshots and captures contain identifying data. Host journal readers, backups, and off-host collectors have separate access and retention policies. Log loss can coincide with a failure. |
| Tampered package or compromised publisher | A pinned reusable workflow enforces protected version tags and reviewed ancestry. Its read-only build job hands off the package and SBOM to a fresh job that attests, signs, verifies, and publishes them. Read-only PR jobs build snapshots. | The operator trusts the reviewed builder revision, source, build inputs, GitHub Actions, and Sigstore roots. Verify the builder revision, release tag, and source commit before installation. A binary SBOM covers embedded components only. |

## Deployment and incident response

The shipped `strict` profile requires Landlock ABI 7+ and successful enforcement. The V7 policy allows filesystem access under the private state directory, denies new TCP binds and connects, and scopes signals and abstract UNIX sockets. Startup queries systemd-resolved's Varlink UNIX socket for default DNS values, then closes it before sandboxing. The unit permits UNIX sockets throughout the worker lifetime; Landlock scopes abstract UNIX sockets but does not by itself block every pathname socket. Existing descriptors retain authority. The explicit `lab-best-effort` profile permits missing kernel rights and always reports degraded protection. Enforcement errors still terminate startup. [Sandbox policy](internal/sandbox/sandbox_linux.go)

For a startup, state, or protection failure, stop the affected socket and service, check the journal for that invocation, and verify a peer instance still serves. Preserve state while repairing the cause. Re-arm only after checking configuration, isolation, and lease recovery. For suspected release compromise, suspend rollout and re-establish the publisher and expected artifact through an independent trusted channel. [Operator commands](README.md#run-one-instance) · [Recovery](TechnicalSpecification.md#persistence-and-recovery)

Restrict access to state, captures, and backups, and expire diagnostic copies when their purpose ends. A snapshot replacement does not erase earlier backups. Correlate journal events using trusted host, unit, boot and invocation metadata. If central receipt matters, monitor it independently of the forwarding path. The example host rules need site-supplied heartbeat expectations and last-receipt time, journal capacity, systemd failures, update status, and privileged-change signals. The examples are opt-in and require site credentials, destinations, and paging routes.
